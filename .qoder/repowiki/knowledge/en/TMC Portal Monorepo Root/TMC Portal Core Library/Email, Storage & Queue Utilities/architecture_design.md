Three sibling utility modules under `lib/` that are consumed by API routes and server components:
- `email.ts` exposes `sendEmail(options)` plus an `emailTemplates` object of prebuilt HTML/text templates (welcome, membershipApproved/Rejected, paymentReceived, verification, officerReminder, weeklyDigest, meetingInvitation, instantCallInvitation, programmeRegistrationReceipt, programmeCertificateThankYou). It uses a singleton `Resend` client initialized from `RESEND_API_KEY`, falls back to dev-mode console logging when the key is absent, and persists every attempt (success/fail) into the `emailLogs` table via `@/lib/db`.
- `storage.ts` is server-only (`import 'server-only'`) and abstracts file uploads: it builds an optional `S3Client` from Wasabi/AWS env vars (`WASABI_*` / `AWS_*`), conditionally compresses images with `sharp` to WebP at max 1920×1080 quality 80 (skippable via `SKIP_IMAGE_COMPRESSION`), writes to S3 returning a `/api/file?key=...` proxy URL or falls back to writing files under `public/uploads/<category>` and returning a local path.
- `queue.ts` defines two BullMQ queues (`email-queue`, `notification-queue`) backed by a shared Redis `connection` from `./redis`, and exports typed job payloads (`EmailJobData`, `NotificationJobData`) used by producers/consumers elsewhere in the app.
Dependency direction is one-way: this module depends on external services (Resend, AWS SDK, Sharp, BullMQ, Redis, Drizzle `db`) but is itself imported by higher-level route handlers; there are no cross-imports between the three files.
