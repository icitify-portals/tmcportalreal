Two parallel implementations coexist: `rbac.ts` is a session-only, in-memory RBAC engine that derives permissions from a static `AdminLevel` enum (`SUPER_ADMIN` … `BRANCH`) via a switch-based mapping and checks organization membership against `officialOrganizationId`/`memberOrganizationId`. `rbac-v2.ts` is the production version backed by Drizzle ORM (`@/lib/db` schema), loading active user roles, role-permission grants, and organization hierarchies through a single multi-join query. It exposes typed domain objects (`UserRole`, `UserPermissions`) and async helpers (`getUserPermissions`, `hasPermission`, `canAccessOrganization`, `hasRole`, `getUserRoles`) plus synchronous session guards (`requirePermission`, `requireRole`). Organization access uses a fixed-depth parent traversal (up to three levels) to build a hierarchy path and compare it against the user's role organization. Tests in `rbac-v2.test.ts` mock the entire `./db` module and use Vitest to assert permission and jurisdiction logic.
