Two independent schema-definition layers coexist in this module, both targeting MySQL:
- `drizzle/` contains Drizzle ORM migrations: a series of numbered SQL files (`0000_giant_demogoblin.sql` through `0013_programme_subaccount.sql`) plus a `meta/_journal.json` that records applied versions. Each file is a self-contained DDL script created by `drizzle-kit`, and the journal tracks which have been applied.
- `prisma/` holds the canonical Prisma model definition in `schema.prisma` (provider `mysql`, generator `prisma-client-js`) and a separate `migrations/` folder with timestamped directories (`20251226032449_init_mysql`, `20260309110000_add_meetings_and_organs`, `20260521160000_add_e2ee_fields_to_messages`) managed by `prisma migrate`. A `seed.ts` provides initial data.

The Prisma schema declares the full domain model (User, Organization hierarchy, Member, Official, Role/Permission RBAC, Payment, Programme, Meeting, Finance, Asset, Backup, etc.) with explicit `@@map` table names, enums, relations, indexes, and cascade rules; it also includes a comment marking models synced from Drizzle, indicating the Prisma schema was generated to mirror the Drizzle state. The two systems are not synchronized automatically — they represent parallel evolution paths of the same underlying MySQL database.
