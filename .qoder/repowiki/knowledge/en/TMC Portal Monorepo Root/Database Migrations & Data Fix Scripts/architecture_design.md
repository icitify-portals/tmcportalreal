Each file is an independent executable script invoked directly (e.g. via `ts-node` or compiled) rather than a shared library. Scripts are grouped by purpose: schema migrations (`alter_db*.ts`, `fix-db-schema.ts`, `add_column*.ts`, `create-*.sql`), data migrations/seeding (`migrate-orgs.ts`, `seed-*.ts`, `assign-superadmin.ts`), diagnostics/checks (`check-*.ts`, `debug-*.ts`, `db-diagnose.js`), backups/export (`backup-db-tables.ts`, `export-db.ts`, `automated-backup.ts`), and deployment helpers (`deploy-prod.ps1`). Most scripts connect to MySQL through either the shared Drizzle ORM client (`../lib/db`) with `drizzle-orm/sql` for parameterized queries, or raw `mysql2/promise` connections for one-off dumps. Environment configuration is loaded per-script via `dotenv` (often manually reading `.env` from `process.cwd()`) so each script can run standalone without a surrounding process. There is no central orchestrator; execution flow is linear top-to-bottom in each file, ending with `process.exit(0)` on success or `process.exit(1)` on failure.
