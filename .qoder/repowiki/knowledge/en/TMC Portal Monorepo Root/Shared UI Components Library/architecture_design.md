Components are organized by domain (auth, admin/*, programmes, meetings, etc.) with a flat `ui/` directory of low-level primitives (button, dialog, table, form, etc.) that every feature component composes. Cross-cutting concerns live at the top level: `theme-provider.tsx` wraps next-themes for global light/dark/system/green theming, `providers/session-provider.tsx` supplies auth/session context, and `shared/client-only.tsx` guards SSR-incompatible client code. Feature directories follow a consistent split between server-rendered page shells and client-side interactive widgets, all importing from the shared `ui/` primitives rather than re-implementing common patterns.
